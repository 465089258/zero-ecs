## 1. 定位与依赖

飞剑能力作为独立领域扩展包存在，不成为 World、Scheduler、Game 之后的第四个核心层：

```text
@zero-ecs/world          @zero-ecs/scheduler
          \              /
             @zero-ecs/game
                    ↑
       @zero-ecs/flying-sword
                    ↑
       examples/flying-sword
```

约束如下：

- 飞剑包只依赖 `@zero-ecs/game` 公共入口，不直接导入 World 或 Scheduler 包。
- 三个核心包不得导入或重导出飞剑包。
- 飞剑包只负责权威 3D 空间数据和领域运行时，不定义相机、视口、2D 投影、屏幕坐标、
  深度渲染队列或绘制层。
- 飞剑包不导入 Canvas、DOM、浏览器 API 或表现模块。
- 示例只使用飞剑包公开入口，不访问内部物理存储。
- 飞剑包独立声明版本和公共 API，不参与核心三包的职责划分。

当前公开入口：

```text
@zero-ecs/flying-sword
@zero-ecs/flying-sword/integration
```

## 2. 世界坐标

数据层使用右手 3D 世界坐标：

```text
+X：角色右方
+Y：上方高度，地面通常为 Y = 0
+Z：角色前方纵深
```

ECS 只保存权威世界坐标、上一固定 Tick 坐标、速度和朝向，不保存 `screenX`、
`screenY` 等表现数据。

## 3. 基础领域身份

每一把实际飞剑是持久 Entity；每个控制组也拥有 Entity 身份。一名角色可以拥有多个
控制组，一把剑同一时刻最多属于一个控制组。

当前基础设施已经实现：

- `FlyingSwordGroupStorage`：控制组内部可写物理存储。
- `FlyingSwordStorage`：飞剑内部可写物理存储。
- `FlyingSwordGroupView`、`FlyingSwordView`：公开只读 QueryProjection。
- `FlyingSwordGroupQuery`、`FlyingSwordQuery`：宿主集成与表现层公共查询。
- `FlyingSwordService`：创建控制组、创建飞剑和提交战术指令。

内部 Storage 不属于包公共入口，调用方不能通过公开 Query 修改飞剑数据。

## 4. 固定帧运行时

`FlyingSwordModule` 要求宿主同时安装 `CommandModule`、`TimeModule`，并注册一个
`FlyingSwordSpatialService` 实现。

当前基础系统顺序：

```text
Request
→ Control
→ Formation
→ Guidance
→ Motion
→ Contact
→ Cleanup
```

基础版本已经实现 Request、Control 和 Motion：

- 浏览器或宿主输入只写请求队列。
- Request System 在固定 Tick 应用控制组指令。
- Control System 通过空间适配器读取控制者坐标并生成组快照。
- Motion System 以速度和加速度限制追随当前环绕槽位。
- 控制组通过 `verticalAmplitude` 和 `verticalSpeed` 定义 Y 轴高度波；各剑按阵位错开
  相位，形成连续的立体升降，而不是表现层伪造的屏幕抖动。
- 每次积分前复制当前位置到 PreviousX/Y/Z，供显示帧插值。

Formation、Guidance、Contact 和 Cleanup 目前是对外稳定系统锚点，完整剑阵编译、轨迹
操作和接触缓冲将在后续阶段实现。

## 5. 宿主空间适配

飞剑库不规定整个游戏必须使用哪种 Transform。宿主通过以下接口提供实体位置：

```ts
abstract class FlyingSwordSpatialService extends Service {
    abstract readPosition(entity: Entity, out: Vector3Out): boolean;
}
```

`out` 由调用方复用，适配器不得在逐剑热路径为坐标创建临时对象。当前示例通过自己的
`Transform3Type` 实现 `DemoFlyingSwordSpatialService`。

## 6. 相机位置与角度

默认相机位于角色后上方，朝角色前方与下方观察。示例使用 `45°` 水平偏角，使世界 X/Z
方格通过真实相机投影自然形成菱形网格；相机仍位于角色后侧半空间。

相机视线与地面夹角定义为：

```text
0°  ：水平观察
90° ：垂直俯视
```

默认角度为 `50°`，推荐可调范围为 `40°～65°`。50° 时：

```text
高度屏幕贡献 cos(50°) ≈ 0.643
纵深屏幕贡献 sin(50°) ≈ 0.766
```

它兼顾地面战斗可读性、飞剑高度、阴影分离和前后剑阵层次。

## 7. 投影与排序

表现层必须从同一组相机基向量同时计算屏幕位置和相机空间深度。当 `yaw = 0` 时：

```ts
cameraRight   = (1, 0, 0);
cameraUp      = (0, cosθ, sinθ);
cameraForward = (0, -sinθ, cosθ);
```

对相机目标的相对坐标 `d = position - cameraTarget`：

```ts
screenX = viewportCenterX + dot(d, cameraRight) * zoom;
screenY = viewportCenterY - dot(d, cameraUp) * zoom;
depth   = dot(d, cameraForward);
```

不得使用世界 Z 或投影后的 screenY 代替 depth。相机转向后 X 也会影响深度，高度 Y
始终影响遮挡关系。

Canvas 使用画家算法：

```ts
layer ascending
→ depth descending
→ subOrder ascending
→ stableId ascending
```

`cameraForward` 指向场景，所以 depth 越大越远；远处对象先绘制。`stableId` 是明确的
平局键，防止同深度对象逐帧抖动。

以下表现设施只属于 `examples/flying-sword/src/presentation`，不属于飞剑 npm 包：

- `TopDownOrthographicCamera`
- `DepthRenderQueue`
- `compareDepthRenderItems`
- `DemoRenderLayer`

示例的 `yaw = 45°` 只改变相机基向量，不使用单独的假菱形坐标。网格、飞剑、阴影、
点击反投影和深度排序始终共用同一个相机。

## 8. 排序锚点

每个渲染原语必须明确排序锚点：

- 飞剑：剑身中点。
- 飞剑阴影：把剑身两端沿世界 Y 轴投影到 `Y = 0`，使用投影后剑身中点排序；复用飞剑
  原始 PNG 的 Alpha 轮廓，以黑色和半透明绘制，从而完整保留剑身、剑尖和剑格，不能
  另画简化轮廓或退化为圆点。
- 角色立绘：脚底。
- 命中特效：3D 接触点。
- 剑光和轨迹：拆分后的短线段中点。

长轨迹不能作为单一对象排序，否则一条轨迹同时跨越近处和远处时无法得到正确遮挡。

## 9. 示例

`examples/flying-sword` 当前展示：

- 一个宿主自定义 Transform3 的修士 Entity。
- 一个控制组和多把飞剑 Entity。
- 飞剑在 XZ 平面环绕，并在 Y 轴上保持飞行高度。
- 飞剑沿 Y 轴以错位相位连续升降；集中时收敛高度幅度，召回时降低高度和波动。
- 固定 60 Hz 模拟和 requestAnimationFrame 插值表现。
- 飞剑、角色和阴影的分层及相机深度排序。
- 世界 X/Z 方格在 45° 水平偏角下投影为菱形背景网格。
- 表现层按 `visualId` 选择青玉、赤金、寒铁或紫电像素飞剑素材，按投影后的剑身方向旋转；
  透视缩短只作用于素材的本地剑身轴，垂直于剑身的像素厚度保持稳定，禁止随转向同时缩放
  两个轴；Canvas 关闭图像平滑以保持像素边缘，素材未加载时才回退到线段。
- 点击地面后反投影到 `Y = 0` 平面并提交集中指令。
- 空格恢复环绕，R 切换召回指令。
- 显示目标 XYZ 和当前最近、最远相机深度。

示例中的相机、2D 投影、反投影、裁剪、深度队列、Canvas、DOM、输入和宿主 Transform
均不进入飞剑包。示例只能通过 `FlyingSwordQuery` 读取公开 3D 数据，再在自己的表现阶段
计算 2D 结果。

Canvas2D 后端只加载 128 像素宽的运行素材；高分辨率原图不进入浏览器产物。黑色 Alpha
阴影和颜色光晕在图片加载后一次性烘焙，稳定帧不执行 `filter` 或 `shadowBlur`。相机屏幕
粗裁剪发生在端点投影和入队之前；静态地面网格使用缓存 Canvas，状态文本降低更新频率。
像素风画布固定使用 DPR 1，避免 DPR 2 带来的四倍填充面积。
