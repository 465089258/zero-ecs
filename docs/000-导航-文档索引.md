## 3. 权威性规则

文档内容冲突时，按以下顺序处理：

1. 规范性架构和规范文档；
2. 已评审的规范性设计文档；
3. 描述当前实现的说明性架构和参考文档；
4. 实施计划与执行记录；
5. 历史归档。

当前代码与说明性文档不一致时，以经过测试的当前代码为事实，并修正文档。当前代码与规范性
文档不一致时，必须明确决定修改代码还是修订规范，不能静默以实现覆盖规范。

## 4. 维护要求

- 新增、重命名、废弃文档时同步更新本索引。
- 状态变化只修改文档元数据和本索引，不修改文件名。
- 文档重命名必须更新仓库内全部相对链接并检查旧名称残留。
- 历史文档不得作为当前 API 或架构事实的唯一来源。
