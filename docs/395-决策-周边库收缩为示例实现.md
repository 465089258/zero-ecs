# 周边库收缩为示例实现

> 类别：决策
> 状态：生效
> 权威性：规范性
> 适用范围：整个仓库
> 最后更新：2026-07-28
> 上位文档：[Zero ECS 架构宪法](./100-架构-架构宪法.md)

## 决策

Zero ECS 只发布和长期维护三个核心包：

```text
@zero-ecs/world          @zero-ecs/scheduler
          \              /
             @zero-ecs/game
```

停止发布和维护 `@zero-ecs/math`、`@zero-ecs/motion` 与
`@zero-ecs/flying-sword`。飞剑示例仍需的 3D 数学组件、运动系统和飞剑领域实现迁入
`examples/flying-sword/src`，作为示例内部代码继续演进。

## 目录与依赖

```text
packages/
├─ world/
├─ scheduler/
└─ game/

examples/flying-sword/src/
├─ infrastructure/
│  ├─ math.ts
│  └─ motion.ts
└─ domain/flying-sword/
```

依赖方向只能是“示例依赖核心”。核心包、核心测试和公开类型契约不得导入示例代码。
示例内部模块不使用 `@zero-ecs/math`、`@zero-ecs/motion` 或
`@zero-ecs/flying-sword` 包名，避免制造仍有公共包的错觉。

## 兼容性

三个被移除的包不再具有公共入口、版本兼容承诺、独立构建任务或发布测试。历史设计文档
保留用于解释方案演进，但不再定义公共包边界；新的框架能力必须先按 World、Scheduler、
Game 三层职责判断归属，具体游戏领域能力默认留在应用或示例中。

## 验证门禁

- 根 workspace 必须且只能包含 World、Scheduler、Game。
- 核心包不得导入示例目录或已移除包名。
- 飞剑示例必须独立通过类型检查、构建和示例测试。
- 发布验证只约束核心三包的 API、包边界、无 JIT 行为和性能规范。
