# 飞剑技能系统设计

> 类别：设计
> 状态：实施中
> 权威性：规范性
> 适用范围：`@zero-ecs/flying-sword`、`examples/flying-sword`
> 最后更新：2026-07-25
> 上位文档：[组合式技能与动作编排设计](./330-设计-组合式技能与动作编排.md)
> 基础设施：[飞剑模块库与 3D 俯视角示例设计](./340-设计-飞剑模块库与3D俯视角示例.md)

本文固定飞剑技能的组合身份、运行边界和首个技能“御剑诀·穿云”的实现语义。飞剑技能
建立在持久飞剑 Entity 和控制组之上，不把最终技能组合编码为新的 Component、System
或 `FlyingSwordMode` 分支。

## 1. 组合身份

飞剑技能由四类内容共同决定：

```text
剑器
+ 御剑诀
+ 剑阵
+ 剑意
= 编译后的 FlyingSwordSkillPlan
```

- 剑器是实际存在的持久 Entity，提供速度、加速度、品质、灵性和载荷基础。
- 御剑诀定义激活、目标选择、动作阶段、投送方式和结束条件，是飞剑技能骨架。
- 剑阵定义多剑槽位、角色分工、空间拓扑和残阵规则。
- 剑意通过能力约束改写轨迹、载荷、接触行为和表现配方。

当前首个垂直切片只内置编译结果 `PiercingCloudSkillPlan`。剑器的基础飞行属性位于独立
领域组件，位置、速度和方向复用 Math 组件，最终运动输入由 Motion 消费；作者态御剑诀、
剑阵和剑意目录及其编译器尚未实现。

## 2. 控制组与技能动作

控制组和技能动作具有不同生命周期：

```text
控制组 = 飞剑池、所有者和默认编队
技能动作 = 临时占用控制组中的部分飞剑
技能结束 = 解除占用并恢复控制组槽位
```

`FlyingSwordMode` 只描述没有技能覆盖时的基础姿态，例如环绕、集中和召回。不得为
“穿云”“剑雨”“弧斩”等技能继续增加 Mode。

同一把飞剑同一时刻最多属于一个技能动作。当前一个控制组只允许一个活跃技能动作；
每个活跃动作拥有独立 Entity。对同一控制组再次施放会复用原动作 Entity 和
`actionSequence`、更新目标并重新进入聚剑阶段，不遗留孤儿占用。

## 3. 公共入口

当前公共技能入口为：

```ts
class FlyingSwordSkillService extends Service {
    cast(options: ActivateFlyingSwordSkillOptions): void;
    cancel(group: Entity): void;
    phase(group: Entity): FlyingSwordSkillPhase;
    sequence(group: Entity): number;
}
```

`cast` 和 `cancel` 只创建一次性 Request Entity。Commands 在 `Update.post` 提交结构，
Request System 在下一固定 Tick 消费；调用方不得直接修改飞剑占用字段或技能动作
Entity。

默认计划：

```ts
FlyingSwordSkillPlanId.PiercingCloud
PiercingCloudSkillPlan
```

宿主可以创建 `FlyingSwordSkillCatalog` 并传给 `FlyingSwordModule`，安装额外的数字化
编译计划。

## 4. 编译计划

`CompiledFlyingSwordSkillPlan` 当前保存以下数字参数：

- 最少和最多飞剑数量；
- 聚剑持续 Tick、到达比例、位置、间距、到达半径和速度倍率；
- 发射波次数量、波次间隔、曲线时长、前视 Tick、爬升高度、转向距离、发射超时和
  速度倍率；
- 贯穿高度、宽度、穿过距离、持续 Tick 和速度倍率；
- 归剑速度、重新入阵半径和确认 Tick；
- 整个动作的强制超时。

稳定帧按数字 `planId` 直接索引计划，不遍历作者对象图。后续内容编译器必须输出相同公共
计划契约，不能让运行时根据御剑诀或剑意名称分支。

## 5. ECS 数据归属

### 5.1 Resource

`FlyingSwordSkillCatalog` 保存只读编译计划。目录创建、校验和扩展发生在冷路径。

### 5.2 State

- `FlyingSwordEntityAccessState`：请求消费者复用的实体位置解析 scratch。
- `FlyingSwordGroupIndexState`：控制组组件在当前固定帧的紧凑 SoA 派生索引。
- `FlyingSwordSkillActionIndexState`：技能动作 Entity 在当前固定帧的紧凑 SoA
  派生索引和工作副本；帧初从组件同步，帧末回写组件。
- `FlyingSwordSkillSequenceState`：只负责分配非零动作序号。

这些 State 都不是请求或动作的权威存储。请求、持久事实和活跃技能动作均可由 Query
观察；State 只承载跨 Chunk 的热路径索引、计数器和可复用 scratch。

### 5.3 控制组级技能动作 Entity

每个活跃技能动作由四个同生命周期组件组成：

```text
FlyingSwordSkillActionEntityStorage
  Group / Plan / Sequence

FlyingSwordSkillTarget3Storage
  X / Y / Z

FlyingSwordSkillTimingStorage
  StartTick / PhaseStartTick
  Stage / DisplayPhase

FlyingSwordSkillAcquisitionStorage（内部）
  State

FlyingSwordSkillProgressStorage
  ReservedCount / RemainingCount
  GatherArrivedCount / ObservedMaximumPhase
```

动作完成后由 Cleanup 通过 Commands 销毁动作 Entity。阶段仍使用固定 Tick 数字推进，
不为每个阶段注册 Timer，也不创建阶段对象。

### 5.4 飞剑持久组件

每把飞剑只长期保留当前稳定行为真正需要的数据：

```text
FlyingSwordMemberStorage
  Group / Slot

FlyingSwordFlightStorage
  MaximumSpeed / Acceleration

Math
  Position3 / PreviousPosition3 / Velocity3 / Direction3

FlyingSwordFormationGoal3Storage
  X / Y / Z

Motion
  MoveTowards3.TargetX/Y/Z
  MoveTowards3.MaximumSpeed / Acceleration / ArrivalRadius
```

`FormationGoal` 是飞剑领域的默认编队输出；Guidance 根据飞剑是否执行技能，把编队目标或
技能轨迹归并为 `MoveTowards3Type`。Motion 不读取控制组、技能计划或飞剑私有组件。

### 5.5 瞬态动作组件

技能开始时，选中的飞剑通过 `Commands` 添加：

```text
FlyingSwordSkillActionStorage
  Action / Phase / PhaseStartTick / Role
  TrajectoryStartX/Y/Z
```

`Action` 是对控制组级技能动作 Entity 的直接关系，不再复制序号作为关联主键；动作
Entity 自身的 `Sequence` 只用于诊断、表现关联和重施放稳定性。

Launch 末段接近目标时再添加 `FlyingSwordContactWindowStorage` 标记；转入 Return 时移除
该标记，重新入阵后移除动作组件。空闲飞剑不携带技能阶段、轨迹起点或接触状态的占位字段。

组件增删由固定提交边界统一执行：System 在 Query 迭代中只构造 EntityCommand，不直接
调用 World 迁移。一次技能阶段切换可以产生结构迁移，但不能因此把不同生命周期的数据
重新合并成长期宽组件。

## 6. 固定 Tick 管线

完整飞剑管线为：

```text
Request
→ Control
→ Skill
→ Formation
→ Guidance
→ MotionSystemSet.Integrate3
→ Orientation
→ Contact
→ Cleanup
```

- Request 先重建技能动作 Entity 的派生索引，再按确定顺序消费控制组与技能 Request
  Entity，并销毁已处理请求。
- 宿主 Integration 在 Control 前把控制者位置同步为控制组中心；飞剑 Control 只生成
  自身控制组快照。
- Skill 通过结构命令为新动作预留飞剑并分配稳定 `ActionRole`。
- Formation 始终计算默认环绕或召回槽位。
- Guidance 根据动作阶段把编队目标或技能轨迹写为最终 Motion 输入。
- Motion 只读取 Math 运动事实与 `MoveTowards3Type` 进行通用积分。
- Orientation 只覆盖没有技能动作组件的 Orbit/Recall 飞剑，使其剑尖朝世界 `+Y`；
  活跃技能飞剑保留 Motion 根据轨迹生成的方向。
- Contact 根据移动后的权威 3D 坐标推进动作阶段，并结构化切换接触窗口。
- Cleanup 在飞剑全部重新入阵后销毁组级技能动作 Entity；逐剑动作组件在归队时移除。

Motion 不认识具体技能计划，也不判断“穿云”名称。

## 7. 御剑诀·穿云

首个技能使用鼠标右键选择 `Y = 0` 地面目标，执行：

```text
Gather
→ Launch
→ Strike
→ Return
→ Rejoin
```

### 7.1 Gather

技能预留当前控制组中可用的飞剑，并根据目标方向在角色周围生成二维聚剑阵列。阵列
相对角色略向后偏移，行列在水平面居中展开；宽度根据飞剑数量开平方计算，避免大量
飞剑形成一条过长横线或全部向后拖成长尾。

Gather 只负责完成角色周围的起手剑阵，不承担高空蓄势。多数飞剑进入聚剑半径，或达到
聚剑最大 Tick 后，动作进入 Launch。

### 7.2 Launch

飞剑根据 `ActionRole % launchWaveCount` 分成固定波次。波次间隔由编译计划保存，不随
飞剑数量线性增长，因此数百把飞剑不会产生数百 Tick 的发射尾部。

每把剑在所属波次真正起飞时，把当前权威 3D 坐标写入 `TrajectoryStartX/Y/Z`，随后
使用三次贝塞尔曲线生成连续前视制导点：

```text
P0 = 每把剑的实际离阵位置
C1 = P0 的正上方
C2 = 目标后上方
P3 = 带横向穿刺偏移的目标点
```

第一控制点使离阵切线朝上，第二控制点让飞剑在高处仍保有水平速度，并逐渐朝目标转向。
因此爬升、转向和俯冲都发生在同一个 Launch 阶段，最高点没有到达判定，也没有停顿。

Guidance 按 `launchCurveTicks` 推进曲线参数，但写入稍靠前的制导点；Motion 继续使用
通用速度和加速度积分追踪前视点。只有曲线时间结束且飞剑抵达目标附近，才进入 Strike。
各剑仍根据角色序号在目标横向形成有限宽度的穿刺面。

### 7.3 Strike

飞剑接近目标后打开接触窗口，并沿“角色到目标”的水平单位方向继续飞行
`passDistance`，形成贯穿而非在目标点停止。

当前只维护 `FlyingSwordContactWindowStorage` 和阶段事实，尚未生成伤害请求。后续
Contact System 应根据上一 Tick 与当前 Tick 的剑身扫掠段生成接触事实，再由宿主战斗
模块结算。

### 7.4 Return 与 Rejoin

完成贯穿或超时后，每把飞剑独立返回当前控制组的动态 FormationGoal。角色移动不会让
飞剑返回旧施法位置。

进入重入半径后切换 Rejoin，保持最少确认 Tick，再清除占用。全部飞剑解除占用后，动作
额外保留一个 Tick 的 Rejoin 状态供表现层观察，然后由 Cleanup 移除。

## 8. 取消、重施放与失效

- 同一控制组重施放：更新目标并重新聚剑，复用当前动作序号。
- `cancel`：强制进入 Return，不瞬间传送或释放飞剑。
- 空格恢复环绕和 R 召回：示例先取消技能，再提交基础控制组指令。
- 动作达到总超时：强制 Return。
- 单剑发射或贯穿阶段超时：该剑独立 Return，不阻塞其他飞剑。
- 飞剑或动作 Entity 关系失配：Guidance/Contact 通过 Commands 清理孤儿动作组件和
  接触窗口。
- 可用飞剑少于 `minimumSwords`：动作直接进入返回和清理。

## 9. 性能边界

- Request 采用一次性 Entity，消费系统按单一请求组件分别查询，避免异构 `kind`
  分支；结构提交延迟属于公共契约。
- 控制组和动作 Entity 的派生索引使用 `count` 游标及高水位复用，稳定帧不创建快照
  对象。
- 飞剑列在进入逐行循环前缓存。
- 每个控制组的方向、正交轴、计划和阵列宽度按连续动作缓存，不为每把剑创建坐标对象。
- 所有轨迹计算直接写入 ECS 数值列。
- 运行时不创建闭包、临时数组、临时向量或每剑阶段对象。
- 公开计划目录使用数字 id 索引；自定义计划校验只发生在目录构造冷路径。

## 10. 当前限制与后续阶段

当前已经实现：

- 数字化计划目录和技能服务；
- 实体化技能请求、组级技能动作 Entity、固定帧派生 SoA 索引和逐剑瞬态动作组件；
- 成员身份、基础飞行属性、Math 运动事实、FormationGoal 与 Motion 最终输入分离；
- 技能预留、接触窗口和归队释放的结构迁移生命周期；
- 角色周围聚剑、分波弧线升空与转向俯冲、贯穿、归剑和重新入阵；
- 取消、同组重施放和分层超时；
- 示例交互、阶段显示和生命周期测试。

后续仍需设计和实现：

1. 剑器、御剑诀、剑阵和剑意的作者态目录及冷路径编译器。
2. 多技能对同一控制组的优先级、排队和部分飞剑选择策略。
3. 套剑、剑匣、残阵、飞剑损毁和失联规则；控制组 `Owner` 当前只表达归属，不触发
   隐式级联销毁，宿主仍负责组和成员 Entity 生命周期。
4. 轨迹扫掠、空间索引、接触事实缓冲和伤害模块集成。
5. 冷却、真元、神识和动作锁；技能实例 Entity 已作为当前运行时权威模型落地。
6. 弧线、螺旋、追踪、往返和持续剑阵等轨迹原语。
