# 飞剑技能系统设计

> 类别：设计
> 状态：实施中
> 权威性：规范性
> 适用范围：`@zero-ecs/flying-sword`、`examples/flying-sword`
> 最后更新：2026-07-25
> 上位文档：[组合式技能与动作编排设计](./330-设计-组合式技能与动作编排.md)
> 基础设施：[飞剑模块库与 3D 俯视角示例设计](./340-设计-飞剑模块库与3D俯视角示例.md)

本文固定飞剑技能的组合身份、运行边界和首个技能“御剑诀·穿云”的实现语义。飞剑技能
建立在持久飞剑 Entity 和控制组之上，不把最终技能组合编码为新的 Component、System
或 `FlyingSwordMode` 分支。

## 1. 组合身份

飞剑技能由四类内容共同决定：

```text
剑器
+ 御剑诀
+ 剑阵
+ 剑意
= 编译后的 FlyingSwordSkillPlan
```

- 剑器是实际存在的持久 Entity，提供速度、加速度、品质、灵性和载荷基础。
- 御剑诀定义激活、目标选择、动作阶段、投送方式和结束条件，是飞剑技能骨架。
- 剑阵定义多剑槽位、角色分工、空间拓扑和残阵规则。
- 剑意通过能力约束改写轨迹、载荷、接触行为和表现配方。

当前首个垂直切片只内置编译结果 `PiercingCloudSkillPlan`。剑器属性仍使用现有飞剑运动
字段；作者态御剑诀、剑阵和剑意目录及其编译器尚未实现。

## 2. 控制组与技能动作

控制组和技能动作具有不同生命周期：

```text
控制组 = 飞剑池、所有者和默认编队
技能动作 = 临时占用控制组中的部分飞剑
技能结束 = 解除占用并恢复控制组槽位
```

`FlyingSwordMode` 只描述没有技能覆盖时的基础姿态，例如环绕、集中和召回。不得为
“穿云”“剑雨”“弧斩”等技能继续增加 Mode。

同一把飞剑同一时刻最多属于一个技能动作。当前一个控制组只允许一个活跃技能动作；对
同一控制组再次施放会复用原 `actionSequence`、更新目标并重新进入聚剑阶段，不遗留孤儿
占用。

## 3. 公共入口

当前公共技能入口为：

```ts
class FlyingSwordSkillService extends Service {
    cast(options: ActivateFlyingSwordSkillOptions): void;
    cancel(group: Entity): void;
    phase(group: Entity): FlyingSwordSkillPhase;
    sequence(group: Entity): number;
}
```

`cast` 和 `cancel` 只写复用请求队列，在固定 Tick 的 Request 阶段生效。调用方不得直接
修改飞剑占用字段或动作 State。

默认计划：

```ts
FlyingSwordSkillPlanId.PiercingCloud
PiercingCloudSkillPlan
```

宿主可以创建 `FlyingSwordSkillCatalog` 并传给 `FlyingSwordModule`，安装额外的数字化
编译计划。

## 4. 编译计划

`CompiledFlyingSwordSkillPlan` 当前保存以下数字参数：

- 最少和最多飞剑数量；
- 升空聚剑持续 Tick、到达比例、位置、间距、到达半径和速度倍率；
- 发射波次数量、波次间隔、发射超时和速度倍率；
- 贯穿高度、宽度、穿过距离、持续 Tick 和速度倍率；
- 归剑速度、重新入阵半径和确认 Tick；
- 整个动作的强制超时。

稳定帧按数字 `planId` 直接索引计划，不遍历作者对象图。后续内容编译器必须输出相同公共
计划契约，不能让运行时根据御剑诀或剑意名称分支。

## 5. ECS 数据归属

### 5.1 Resource

`FlyingSwordSkillCatalog` 保存只读编译计划。目录创建、校验和扩展发生在冷路径。

### 5.2 State

- `FlyingSwordSkillRequestState`：高水位复用的激活和取消请求队列。
- `FlyingSwordSkillActionState`：活跃动作的紧凑 SoA 数据。

动作 State 保存：

```text
group / planId / actionSequence
targetX / targetY / targetZ
startTick / phaseStartTick
stage / displayPhase
reservedCount / remainingCount
```

短生命周期技能动作不创建临时 Entity，也不为每个阶段注册 Timer。

### 5.3 飞剑稳定字段

每把飞剑长期保留以下运行字段，施法时不添加或删除 Component：

```text
FormationGoalX/Y/Z
GoalX/Y/Z
ArrivalRadius
SpeedMultiplier
AccelerationMultiplier
ActionSequence
ActionPhase
ActionPhaseStartTick
ActionRole
ContactActive
```

`ActionSequence = 0` 表示当前没有被技能占用。`FormationGoal` 是控制组默认目标，`Goal`
是经过技能制导覆盖后交给 Motion 的最终目标。

## 6. 固定 Tick 管线

完整飞剑管线为：

```text
Request
→ Control
→ Skill
→ Formation
→ Guidance
→ Motion
→ Contact
→ Cleanup
```

- Request 应用控制组指令和技能请求。
- Control 同步控制者位置并生成控制组快照。
- Skill 为新动作预留飞剑并分配稳定 `ActionRole`。
- Formation 始终计算默认环绕或召回槽位。
- Guidance 根据动作阶段覆盖被占用飞剑的最终目标。
- Motion 只读取最终目标、速度倍率和加速度倍率进行通用积分。
- Contact 根据移动后的权威 3D 坐标推进动作阶段。
- Cleanup 在飞剑全部重新入阵后移除动作记录。

Motion 不认识具体技能计划，也不判断“穿云”名称。

## 7. 御剑诀·穿云

首个技能使用鼠标右键选择 `Y = 0` 地面目标，执行：

```text
Gather
→ Launch
→ Strike
→ Return
→ Rejoin
```

### 7.1 Gather

技能预留当前控制组中可用的飞剑，并根据目标方向在角色上空生成二维聚剑阵列。阵列以
角色上方为中心、向角色身后略微偏移；行列在水平面居中展开，宽度根据飞剑数量开平方
计算，避免大量飞剑形成一条过长横线或全部向后拖成长尾。

默认聚剑高度明显高于常态环绕高度，飞剑首先形成清晰的上升轨迹。多数飞剑进入高空
聚剑半径，或达到聚剑最大 Tick 后，动作才进入 Launch。

### 7.2 Launch

飞剑根据 `ActionRole % launchWaveCount` 分成固定波次。波次间隔由编译计划保存，不随
飞剑数量线性增长，因此数百把飞剑不会产生数百 Tick 的发射尾部。

各剑从高空阵列俯冲至目标上方，并根据角色序号在目标横向形成有限宽度的穿刺面。
Launch 使用高于聚剑和常态运动的速度、加速度倍率，使升空蓄势与向下冲刺在轨迹和
节奏上形成明显反差。

### 7.3 Strike

飞剑接近目标后打开接触窗口，并沿“角色到目标”的水平单位方向继续飞行
`passDistance`，形成贯穿而非在目标点停止。

当前只维护 `ContactActive` 和阶段事实，尚未生成伤害请求。后续 Contact System 应根据
上一 Tick 与当前 Tick 的剑身扫掠段生成接触事实，再由宿主战斗模块结算。

### 7.4 Return 与 Rejoin

完成贯穿或超时后，每把飞剑独立返回当前控制组的动态 FormationGoal。角色移动不会让
飞剑返回旧施法位置。

进入重入半径后切换 Rejoin，保持最少确认 Tick，再清除占用。全部飞剑解除占用后，动作
额外保留一个 Tick 的 Rejoin 状态供表现层观察，然后由 Cleanup 移除。

## 8. 取消、重施放与失效

- 同一控制组重施放：更新目标并重新聚剑，复用当前动作序号。
- `cancel`：强制进入 Return，不瞬间传送或释放飞剑。
- 空格恢复环绕和 R 召回：示例先取消技能，再提交基础控制组指令。
- 动作达到总超时：强制 Return。
- 单剑发射或贯穿阶段超时：该剑独立 Return，不阻塞其他飞剑。
- 飞剑或动作记录失配：Guidance/Contact 清理孤儿占用。
- 可用飞剑少于 `minimumSwords`：动作直接进入返回和清理。

## 9. 性能边界

- 请求和动作数组使用 `count` 游标及高水位复用。
- 飞剑列在进入逐行循环前缓存。
- 每个控制组的方向、正交轴、计划和阵列宽度按连续动作缓存，不为每把剑创建坐标对象。
- 所有轨迹计算直接写入 ECS 数值列。
- 运行时不创建闭包、临时数组、临时向量或每剑阶段对象。
- 公开计划目录使用数字 id 索引；自定义计划校验只发生在目录构造冷路径。

## 10. 当前限制与后续阶段

当前已经实现：

- 数字化计划目录和技能服务；
- 技能请求、动作 SoA 和飞剑稳定占用字段；
- 默认 FormationGoal 与最终 Goal 分离；
- 升空聚剑、分波俯冲、贯穿、归剑和重新入阵；
- 取消、同组重施放和分层超时；
- 示例交互、阶段显示和生命周期测试。

后续仍需设计和实现：

1. 剑器、御剑诀、剑阵和剑意的作者态目录及冷路径编译器。
2. 多技能对同一控制组的优先级、排队和部分飞剑选择策略。
3. 套剑、剑匣、残阵、飞剑损毁和失联规则。
4. 轨迹扫掠、空间索引、接触事实缓冲和伤害模块集成。
5. 冷却、真元、神识、动作锁和技能实例 Entity。
6. 弧线、螺旋、追踪、往返和持续剑阵等轨迹原语。
