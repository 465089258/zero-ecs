## 1. 目标

飞剑肉鸽示例增加四条彼此独立的成长轴：

```text
剑夹容量        决定最多持有多少把剑
神识            决定同时操控多少把剑
单剑属性        决定每把剑的伤害、攻击间隔和飞行能力
单剑灵力        决定每把剑连续作战时间及后备轮换
```

人物法力既是维持剑阵的控制组资源，也是集火一次性爆发的蓄力资源；身剑合一继续消耗
体力。法力、体力和飞剑灵力不得
合并为同一数值。

## 2. ECS 建模原则

Archetype 用于表达实体当前拥有的能力和参与的 System 集合：

- 受控、后备、等待退役、集火冲锋、分散任务和剑阵参与使用 Tag 或可选组件表达；
- 位置、速度、当前灵力、伤害、攻击间隔、目标和 Tick 进度使用组件字段表达；
- 正常的低频结构迁移不得为了规避迁移成本退化为超宽组件加状态分支；
- 同一 Commands 批次中的结构意图必须归并为实体最终组件集合。

`ControlledFlyingSwordTag` 与 `ReserveFlyingSwordTag` 互斥。灵力耗尽但当前动作尚未
结束时，`PendingFlyingSwordRetireTag` 可以暂时与 `ControlledFlyingSwordTag` 共存。

## 3. 数量与归属

```text
ownedSwordCount <= containerCapacity
controlledSwordCount <= spiritualSenseLimit
controlledSwordCount <= ownedSwordCount
```

剑夹是独立 Entity，保存 Owner 与 Capacity。每把剑通过容器关系和稳定 InventorySlot
归属于剑夹。受控剑另外拥有 `SwordControlAssignment`，其中 ControlSlot 是当前神识控制位，
不得与 InventorySlot 混用。

提升神识、获得飞剑或更换剑夹后，控制权按稳定规则重新归并。无法操控的剑进入角色后上方
的扇形后备阵列，不参与索敌、攻击、剑阵或身剑合一。

## 4. 单剑属性

每把剑独立保存：

- Blueprint、Quality 与 Visual；
- MinimumDamage 与 MaximumDamage；
- AttackIntervalTicks；
- MaximumSpeed 与 Acceleration；
- CurrentSpirit、MaximumSpirit、RecoveryPerSecond 与 RecoveryDelayTicks；
- Target、NextAttackTick 与 AttackSequence 等运行数据。

一次攻击使用单剑 Entity 与 AttackSequence 产生可复现的伤害值。控制组不再
保存统一基础伤害，只保留御剑全局倍率、姿态倍率、索敌范围、剑意和阵图参数。

## 5. 灵力与自动轮换

分散攻击和集火在动作开始时扣除固定单剑灵力；剑阵中的每把剑按秒消耗灵力。后备剑经过
恢复延迟后按秒恢复灵力。

活动剑耗尽后的候补规则：

1. 当前动作未完成时添加 `PendingSwordRetireTag`；
2. 动作完成后迁移为后备剑；
3. 从达到最大灵力一定比例的后备剑中选择候补；
4. 优先选择灵力比例最高者，再按 InventorySlot 打破平局；
5. 候补剑继承旧剑 ControlSlot 并迁移为受控剑；
6. 没有可用候补时允许 ControlSlot 暂时空缺。

换下不会瞬间回满灵力。更多飞剑增加持续作战深度，更多神识增加同时输出数量。

## 6. 战斗方式

### 6.1 分散

受控剑分别维护目标、攻击间隔和灵力。每把剑独立索敌、出击、返回，不等待其他飞剑。

### 6.2 集火

右键后所有可用受控剑从各自当前位置直接沿直线冲向目标点，不聚剑、不升空、不停顿。
每条路径对经过的全部敌人造成该剑的独立伤害；同一把剑在同一次 Action 内不得重复命中
同一敌人。目标点相对角色中心的水平距离限制为 5～14 个世界单位，过近时沿点击方向延伸，
过远时沿点击方向截断；目标提示、技能动作和伤害路径必须使用同一夹紧结果。到达目标后
返回当前姿态。集火有 25 点最低法力启动条件，确认施放后一次消耗全部当前法力；本次
Action 的伤害倍率为 `1 + 消耗法力 / 100`。消耗量和倍率必须作为 Action 事实保存，禁止
在延迟命中时回读玩家当前法力。

### 6.3 剑阵

只有受控剑进入阵图。人物法力按“基础消耗 + 参与飞剑数 × 单剑消耗”持续下降；法力耗尽
时同一固定 Tick 内退出剑阵并切换分散。每把阵中剑还会独立消耗自身灵力，耗尽时只轮换
该剑，不中断整个剑阵。

### 6.4 身剑合一

只有受控剑组成伞状钻头。发动后先进入 18 个固定 Tick 的聚剑阶段：人物停住，飞剑形成
初始伞状结构且可跟随输入调整方向；完成后才进入突进阶段、开始人物位移和体力消耗，
接触伤害也只在突进阶段开放。第一阶段维持既有身剑合一伤害模型，不在该动作内消耗
单剑灵力；后续若引入单剑贡献，需要单独设计连续接触的伤害聚合规则。

## 7. 获得飞剑与展示

升级候选不再只保存升级 ID，而以短生命周期 Offer Entity 表达。获得飞剑 Offer 必须包含
本次实际生成的 Blueprint、Quality、伤害上下限、攻击间隔、飞行速度、加速度、最大灵力
与回灵速度。表现层读取同一份 Offer 数据，选择后原样复制到新剑，保证预览和实际一致。

剑夹已满时不生成“获得飞剑”候选。获得飞剑后，神识有空位则立即部署，否则进入后备扇形。
HUD 显示持剑数量/容量、实际受控数量/神识上限、人物法力，以及升级卡中的完整单剑属性。

## 8. 固定 Tick 顺序

```text
升级与装备请求
→ 剑夹归属和神识控制权归并
→ 后备回灵与耗尽剑轮换
→ 人物法力恢复、剑阵消耗和耗尽降级
→ 输入与动作创建
→ 分散、集火、剑阵及后备目标计算
→ 飞剑运动
→ 接触检测与单剑伤害请求
→ 剑意和全局倍率
→ 统一伤害结算
→ 表现同步
```

## 9. 第一阶段约束

- 单个剑夹容量上限为 64，与当前集火双 U32 命中掩码一致；
- 示例暂时只装备一个剑夹；
- 获得飞剑在容量已满时不可选；
- 候补出战阈值默认为最大灵力的 50%；
- 所有热路径继续遵守 Chunk 列缓存和无逐项对象分配规范。
