## 1. 定位

`@zero-ecs/math` 是服务 Zero ECS 的可选基础扩展，不是脱离 ECS 的普通对象数学库：

```text
@zero-ecs/world          @zero-ecs/scheduler
          \              /
             @zero-ecs/game
                    ↑
             @zero-ecs/math
```

数学包只依赖 `@zero-ecs/game` 公共入口；World、Scheduler 和 Game 不反向依赖或重导出
数学包。它定义 ECS 数学组件、共享字段布局和无逐项分配运算。持久向量、角度、四元数、
矩阵和包围体都使用 ComponentType 表达。

当前公共入口：

```text
@zero-ecs/math
@zero-ecs/math/2d
@zero-ecs/math/3d
@zero-ecs/math/projection
```

相机、视体裁剪和 3D→2D 投影位于同一包的 `projection` 子模块，不建立只有投影能力的
单独薄包。

## 2. 字段与组件命名

同构数值布局使用普通数字枚举：

```ts
export enum Float3 {
    X,
    Y,
    Z,
}

export class Position3Type implements Component<Float3> {
    readonly [Float3.X] = Types.F32;
    readonly [Float3.Y] = Types.F32;
    readonly [Float3.Z] = Types.F32;
}
```

规则如下：

- 跨包字段使用普通 `enum`，不使用 `const enum`。
- 枚举成员不通过 `=` 手动赋值，自然形成从 0 开始的连续编号。
- 允许重排和在任意位置增加字段；内部数字编号不是稳定序列化协议。
- 所有组件声明和字段访问必须使用枚举，禁止用 `0/1/2` 等字面量表达字段身份。
- ComponentType 使用“语义 + 维度 + `Type`”，例如 `Position3Type`。
- 同一 Entity 可以同时拥有共享 `Float3` 布局的 `Position3Type`、`Velocity3Type` 和
  `Direction3Type`；布局相同不代表 ComponentType 身份相同。
- 单字段数据不用没有语义价值的 `Float1`；角度使用 `Angle.Radians`，角速度使用
  `AngularVelocity.RadiansPerSecond`。
- AABB、Sphere、Plane、Ray 等字段含义不同或存储类型异构的数据使用自己的语义枚举。

## 3. 坐标与矩阵约定

- 世界坐标使用右手系：`+X` 向右、`+Y` 向上、`+Z` 向前。
- 角度统一使用弧度。
- `Float3x3`、`Float4x4` 字段使用 `M行列` 命名。
- 矩阵运算使用列向量约定，组合顺序为 `Translation × Rotation × Scale`。
- 二维平移位于 `M02/M12`，三维平移位于 `M03/M13/M23`。
- 矩阵组件按需添加；普通实体不因使用 Position/Rotation/Scale 自动承担完整矩阵的
  9 或 16 个 F32 字段。

## 4. 组件范围

当前 2D 组件包括：

```text
Vector2Type

Velocity2Type / Acceleration2Type / Direction2Type / Scale2Type
Rotation2Type / AngularVelocity2Type
Matrix3Type / LocalMatrix3Type / WorldMatrix3Type

```

当前 3D 组件包括：

```text
Vector3Type
Position3Type / PreviousPosition3Type / RenderPosition3Type
LocalPosition3Type / WorldPosition3Type
Velocity3Type / Acceleration3Type / Direction3Type / Scale3Type
AngularVelocity3Type
QuaternionType / Rotation3Type

```

领域包可以复用 `Float2/Float3/Float4` 声明自己的语义组件，不要求把所有向量角色加入数学包。

## 5. 角度与圆周变化

`Rotation2Type` 表达一个圆周内的规范方向；`AngularPhaseType` 表达可以跨越多个圆周的连续
相位。角度插值使用最短圆弧：

```text
wrapRadians
shortestAngleDelta
lerpAngle
```

圆周运动应插值相位后通过 `sin/cos` 重建位置，不能在线性插值两个圆周位置后把弦误当成圆弧。
3D 旋转使用单位四元数和最短弧 `slerpQuaternion`。

## 6. GC 与热路径

数学包遵守全框架 Chunk 列缓存规范：

```ts
const xs = data[Float3.X];
const ys = data[Float3.Y];
const zs = data[Float3.Z];

for (let row = 0; row < count; row++) {
    // 只访问局部 TypedArray。
}
```

约束如下：

- 稳定数学热路径不创建临时向量、矩阵、数组、对象、元组、迭代器或闭包。
- 多值结果写入调用方提供的 ECS 组件列和行；调用方负责复用输出存储。
- 标量结果直接返回 number 或 boolean。
- 规范化零向量时原地写零，不返回结果对象。
- 矩阵、四元数和向量运算先把输入读入局部 number，再写输出，因此允许输入输出指向
  相同组件列和行。
- 不依赖 JIT 逃逸分析来宣称零分配。
- 第一阶段不增加模块级 `const FLOAT3_X = Float3.X` 字段编号缓存；是否引入只由正式
  JIT、`--jitless` 和 Chromium 配对基准决定。

## 7. 相机、裁剪与投影

活动正交相机 Entity 由以下组件组成：

```text
Position3Type
TopDownCamera3Type
OrthographicCameraType
CameraBasis3Type
CameraWorldAabb3Type
ActiveCameraTag
```

`TopDownCamera3Type` 保存 yaw 和视线与地面的 elevation；`OrthographicCameraType` 保存
视口、每世界单位像素数、近远深度和世界单位裁剪边距。`CameraBasis3Type` 与
`CameraWorldAabb3Type` 是每帧原地更新的派生缓存。

参与投影的实体持有：

```text
Position3Type
ProjectionBounds3Type
Projected2Type
```

`Projected2Type` 永久保留 X、Y、相机空间 Depth 和 Visible。视野外实体只写
`Visible = 0`，不删除组件，也不覆盖最近一次有效坐标和深度。这样实体重新进入视野时不
发生 Archetype 迁移，表现层也能明确拒绝陈旧结果。没有活动相机时，System 同样只把全部
投影结果标记为不可见。

`orthographicProjectionSystem` 默认在 `Update.last` 执行。自定义表现阶段通过
`defineOrthographicProjectionSystem(stage)` 创建同一批处理 System。每帧顺序固定为：

```text
更新相机正交基向量
→ 更新相机视体的世界 AABB
→ 包围球与世界 AABB 粗裁剪
→ 相机空间正交视体精裁剪
→ 只投影可见实体并写入 X/Y/Depth/Visible
```

Depth 与屏幕坐标来自同一相机 Forward/Right/Up 基向量。画家算法使用
`layer ascending → depth descending → subOrder ascending → Entity ascending`；
不能用世界 Z 或屏幕 Y 代替 Depth。

Projection System 在相机级和每个 Projectable Chunk 入口缓存字段列，逐实体循环只保留
局部 number 和 TypedArray 访问。查询迭代器由 Query 复用，稳定帧不创建临时向量、平面、
角点、结果对象或闭包。

## 8. 当前阶段与后续

当前阶段已完成组件布局、角度、向量、矩阵、四元数、基础包围体、正交相机、世界 AABB
粗裁剪、精确视体裁剪和批量投影。飞剑与示例已经迁移到通用 `Position3Type`、
`PreviousPosition3Type`、`Velocity3Type` 和 `Direction3Type`；运动积分已进入独立的
`@zero-ecs/motion`，没有反向塞入 Math。后续顺序为：

1. 评估由飞剑示例在表现层接入通用 Projection System，不把相机或投影结果反向放入
   飞剑包。
2. 增加透视相机及其视锥平面缓存。
3. 建立独立数学基准，再决定字段缓存、批量内核和空间索引。
