> 最后更新：2026-07-26
> 上位文档：[飞剑模块库与 3D 俯视角示例设计](./340-设计-飞剑模块库与3D俯视角示例.md)
> 飞剑运行时：[飞剑技能系统设计](./360-设计-飞剑技能系统.md)
> 模块边界：[可插拔 ECS 模块设计规范](./220-规范-可插拔ECS模块.md)
> 后续计划：[飞剑肉鸽后续完善执行方案](./720-计划-飞剑肉鸽后续完善.md)

本文把现有“飞剑基础设施展示”改造为中式修仙题材的俯视角幸存者式肉鸽。这里的
“肉鸽”指实时移动、自动战斗、波次生存、经验升级、随机三选一和单局构筑；第一阶段
不实现地图探索、房间生成、永久养成或回合制传统 Roguelike。

## 1. 产品定位

单局目标：

```text
进入试炼
→ 抵御持续增强的妖潮
→ 收集灵蕴并升级
→ 组合剑器、御剑诀、剑阵和剑意
→ 第 8 分钟迎战首领
→ 击败首领或角色身死
→ 结算并可立即重开
```

首个版本应是一局 8～12 分钟、可以反复构筑的完整游戏闭环，而不是在原演示中简单增加
几个追逐角色的圆点。

推荐操作：

- `WASD`：连续移动；保留鼠标左键点击地面移动作为辅助操作。
- 分散御剑：每把空闲飞剑独立索敌并错峰出剑。
- 鼠标右键：向指定地面位置集火施放御剑诀，覆盖一次自动目标。
- `Q`：在分散御剑与剑阵之间切换。
- `R`：召回飞剑，在角色身后形成动态防御扇阵。
- `Space`：向鼠标方向施放身剑合一。
- `1/2/3` 或鼠标点击：选择升级。
- `Esc`：暂停。

分散御剑负责基础战斗节奏，右键集火、剑阵、召回和身剑合一提供主动操作空间。

三种战斗形态必须使用真实飞剑实体表达运动，表现层不得绘制一组与飞剑位置无关的假剑：

- 分散御剑：单剑错峰出发，沿同一条连续的“升空—转向—俯冲”曲线攻击，命中或超时后
  独立返阵，不等待同组其他飞剑。
- 剑阵：飞剑分组沿外层多边形与内层交织路径运行，不以所有飞剑绕角色画同一个圆作为
  最终效果。不同路径允许不同速度、方向和高度，使飞剑在运动中共同显现阵图。
- 身剑合一：施放时立即中断未完成的单剑任务；角色位移的同时，飞剑全部位于突进方向
  前方，组成由宽到窄的锥形螺旋钻头并随角色移动。剑尖主要朝突进轴，螺旋切向只用于
  保留旋转动势。

## 2. 架构边界

### 2.1 `@zero-ecs/flying-sword` 继续负责

- 控制组、飞剑成员、编队和基础控制模式。
- 飞剑 3D 位置、方向、技能动作与接触窗口。
- 编译后的飞剑技能计划和技能动作生命周期。
- 只读飞剑、技能动作和接触 Query。

### 2.2 肉鸽示例负责

- 玩家生命、移动输入和死亡。
- 敌人生成、AI、生命、接触伤害和死亡。
- 自动索敌与何时施放技能。
- 飞剑接触如何转换为伤害。
- 灵蕴掉落、吸附、拾取、等级和升级选择。
- 本局 Build、元素剑意、数值结算和胜负。
- 敌人、掉落物、伤害数字、HUD、升级面板和结算表现。

飞剑库不得导入 Enemy、Health、Experience、Upgrade、DOM 或 Canvas。战斗含义集中在
示例的 FlyingSword-Combat Integration 中。

### 2.3 需要补充的飞剑窄 API

“增加飞剑”升级需要同步控制组编队容量。现有 Storage 不公开，因此先补充：

```ts
FlyingSwordService.setFormationSize(
    group: Entity,
    size: number,
): void;
```

该调用生成独立 Request Entity，在下一固定 Tick 修改
`FlyingSwordFormationStorage.Size`。新增飞剑使用末尾 Slot，已有飞剑无需重排。

第一阶段不开放任意内部编队字段写入，不为示例暴露 Storage。技能数值升级优先使用预编译
计划 ID，不在运行时修改 `FlyingSwordSkillCatalog`。

## 3. 单局核心循环

### 3.1 敌潮

敌人在玩家相机外、模拟半径内的环带生成，持续向玩家移动。Director 使用“威胁预算”
而不是固定每波数量：

```text
每秒预算 = 基础预算 + 时间成长 + 波次修正
敌人消耗 = 生命、速度、体型、能力的综合成本
```

第一阶段包含：

| 敌人 | 定位 | 特征 |
| --- | --- | --- |
| 妖蚀蝠 | 快速杂兵 | 低生命、高速度、小体型 |
| 腐骨傀 | 普通近战 | 中等生命与速度 |
| 镇山石傀 | 重型敌人 | 高生命、低速度、大碰撞半径 |
| 剑魇精英 | 精英 | 周期强化附近敌人，掉落更多灵蕴 |
| 赤目剑魇 | 首领 | 第 8 分钟出现，阶段性冲锋和召唤 |

远程弹幕和复杂首领阶段放在第二阶段。

### 3.2 自动御剑

玩家控制组拥有示例侧 `AutoFlyingSwordSkill` 组件：

```text
Plan / CooldownTicks / NextCastTick
TargetRadius / TargetPolicy
```

冷却完成后，Targeting 从空间索引中选择目标：

1. 优先精英和首领；
2. 否则选择有效半径内最近的敌群中心；
3. 没有目标则不消耗冷却；
4. 手动右键目标优先于一次自动目标。
5. 一次施法为每把参与飞剑分配独立目标点；候选敌人不足时才循环复用目标。

Targeting 只调用 `FlyingSwordSkillService.cast`。Request Entity 在 `Update.post` 提交并于
下一固定 Tick 消费；这一 Tick 延迟属于确定性管线的一部分。

### 3.3 飞剑伤害

示例组合以下公共投影：

```text
FlyingSwordView
+ FlyingSwordActionView
+ FlyingSwordContactWindow
+ PreviousPosition3View
+ Position3View
```

接触系统使用飞剑上一固定帧到当前固定帧的扫掠段查询附近敌人。命中后生成示例自有的
`DamageRequest` Entity，由 Damage System 在下一 Tick 结算。

同一次技能动作不能每 Tick 重复伤害同一敌人。敌人保存：

```text
LastFlyingSwordAction
LastFlyingSwordActionStartTick
```

动作 Entity 在同组重施放时会复用，因此去重键必须同时包含动作 Entity 和
`FlyingSwordSkillTiming.StartTick`，不能只使用 Action 或稳定 Sequence。

第一版按“每个敌人每次技能动作最多结算一次”聚合伤害，伤害可以根据本次预留剑数缩放；
不建立 `sword × enemy` 的巨大命中历史。

伤害数字由示例侧独立 `DamageDisplayModule` 消费 `DamageRequest` 生成短生命周期表现实体，
不进入飞剑领域组件，也不让战斗系统依赖 Canvas。

### 3.4 受伤与死亡

敌人与玩家发生地面 XZ 圆形接触时提交伤害请求，并为敌人记录下一次允许接触伤害 Tick。
玩家生命降为零后把 Run Entity 切换为 Defeat，停止生成、AI 和伤害系统，但继续渲染和
结算 UI。

敌人死亡产生 Death Fact，后续系统独立处理：

- 增加击杀数；
- 生成灵蕴；
- 触发精英或首领奖励；
- 播放表现；
- 通过 Commands 销毁敌人。

## 4. 局内成长

### 4.1 等级

敌人掉落灵蕴 Entity。玩家进入吸附半径后，灵蕴向玩家加速；进入拾取半径后增加经验。
升级所需经验采用缓慢超线性曲线：

```text
required(level) = round(8 + 5 × level^1.35)
```

一次获得多级经验时逐级生成选择，不丢失溢出经验。

### 4.2 四种战斗路线与通用成长

首版升级直接强化当前已经可以操作的四种战斗路线；飞剑数量、基础伤害和生存属性作为
通用成长：

| 路线 | 示例升级 | 运行效果 |
| --- | --- | --- |
| 集火·归一 | 贯日 | 提高集火剑诀的独立伤害倍率 |
| 分散·分光 | 行气无滞、神识扩域 | 缩短单剑返阵间隔，扩大自动索敌范围 |
| 剑阵·周天 | 剑罡、疾旋 | 提高持续接触伤害，缩短同目标触发间隔 |
| 位移·合一 | 摧岳、流转、踏虚 | 提高突进伤害，缩短冷却，增加突进距离 |
| 通用 | 添置飞剑、淬炼剑锋、身法、护体、聚灵 | 强化所有路线或生存与收集能力 |

当前升级池包含 13 项，飞剑数量上限 49；剑阵与身剑合一的触发间隔都有硬下限，避免
重复升级后退化为每 Tick 伤害。后续雷、火、寒、金剑意仍由战斗 Integration 解释，
不能写进 `FlyingSwordMode` 或飞剑基础组件。

元素效果由战斗模块解释，不能写进 `FlyingSwordMode` 或飞剑基础组件。

### 4.3 随机与重放

Run Entity 保存种子和 RNG 状态。敌人生成、升级抽取和掉落都使用同一确定性整数 RNG，
禁止在系统热路径直接调用 `Math.random()`。

升级三选一必须：

- 同一批次不重复；
- 排除已经满级的升级；
- 至少保留一个当前可用选项；
- 使用升级 ID 和等级，不保存作者对象引用；
- 暂停固定模拟，选择完成后恢复。

第一阶段只有局内成长，不保存跨局货币和永久天赋。

## 5. ECS 数据模型

### 5.1 Entity

| Entity | 主要组件 |
| --- | --- |
| Run | `RunIdentity`、`RunClock`、`RunPhase`、`RunRandom`、`RunStatistics` |
| Player | Math/Motion、`CultivatorTag`、`Health`、`LevelExperience`、`PlayerMovement` |
| Sword Group | 飞剑库组件、`AutoFlyingSwordSkill`、`SwordCombatBuild` |
| Flying Sword | 飞剑库组件、示例视觉组件 |
| Enemy | Math/Motion、`EnemyIdentity`、`Health`、`EnemyCombat`、`ExperienceReward` |
| Experience Orb | Math/Motion、`ExperiencePickup` |
| Damage Request | `DamageRequest` |
| Death Fact | `DeathFact` |
| Upgrade Request | `ChooseUpgradeRequest` |

### 5.2 Resource

- `EnemyCatalog`：只读敌人数值和视觉 ID。
- `UpgradeCatalog`：只读升级约束、稀有度和最大等级。
- `RunTuning`：局时、生成预算、空间半径和经验曲线。
- `FlyingSwordSkillCatalog`：飞剑库已有的只读技能计划。

### 5.3 State

State 只保存技术性运行缓存：

- `EnemySpatialIndexState`：固定帧派生的敌人网格索引。
- `TargetingScratchState`：目标候选和聚类临时缓冲。
- `CombatScratchState`：扫掠查询与伤害聚合缓冲。
- 当前已有的输入、渲染帧和渲染队列缓存。

Run、生命、经验、Build、敌人和掉落都必须是组件事实，不得继续扩张
`DemoSceneState` 形成新的全局业务对象。

## 7. 固定 Tick 管线

```text
Input
→ Run / Upgrade Request
→ Enemy Spawn
→ Enemy Intent
→ Player Movement Intent
→ Auto Targeting / Flying Sword Cast Intent
→ FlyingSword Request / Control / Skill / Formation / Guidance
→ MotionSystemSet.Integrate3
→ FlyingSword Orientation / Contact
→ Enemy Spatial Index
→ FlyingSword-Enemy Sweep
→ Player-Enemy Contact
→ Damage Resolve
→ Death Facts
→ Drop / Pickup
→ Experience / Level Up
→ Cleanup
→ Update.post Commands
```

结构命令产生的 Request、敌人、掉落和动作组件均在 `Update.post` 提交。系统不能假设
本 Tick 创建的 Entity 会在同一固定阶段被查询到。

升级选择期间由主循环停止推进 `game.update()`，但继续执行表现 Stage；不能让固定时间在
选择界面后台增长。选择结果先成为 Request Entity，恢复后由下一固定 Tick 应用。

## 8. 空间索引与性能

目标规模：

- 正常局面：500～1000 个敌人、7～81 把飞剑。
- 压力模式：2000 个敌人、500 把飞剑。
- 固定模拟 60 Hz；表现尽量维持 60 FPS。

敌人索引采用玩家中心的固定范围均匀网格：

- 单元尺寸约 1.5～2 世界单位；
- `Int32Array` 保存 cell head 和 next；
- 每 Tick `fill(-1)` 后按敌人 Query 重建；
- State 数组高水位复用，不创建每敌人对象；
- 自动索敌、飞剑扫掠和雷意连锁共用同一派生索引；
- 超出模拟半径的普通敌人回收或销毁，首领除外。

热路径要求：

- Chunk 列在逐行循环前缓存；
- 不创建临时向量、闭包、候选对象或逐次命中数组；
- 接触先做网格候选，再做扫掠段与球体精确测试；
- 同 Tick 伤害按目标聚合，限制 Damage Request 数量；
- 敌人生成按 Tick 分批，避免单帧大量 Archetype 迁移；
- Canvas 先相机裁剪，再投影和入深度队列；
- 敌人、灵蕴和伤害数字使用图集或批量路径，不使用稳定帧 `filter`、`shadowBlur`。

压力参数继续使用 URL：

```text
?swords=500&enemies=2000&seed=12345
```

## 9. 表现与 UI

世界表现保留当前 3D 数据到俯视角 2D 投影、深度排序、飞剑素材与阴影。

新增：

- 地面敌人、精英描边、首领体型和受击闪白；
- 灵蕴吸附轨迹；
- 伤害数字池；
- 玩家生命、经验、等级、局时、击杀数和首领条；
- 当前剑数、自动施放冷却、御剑诀等级和剑意图标；
- 升级三选一遮罩；
- 胜利、失败和重开界面。

HUD 使用 DOM；大量世界对象使用 Canvas。升级界面必须支持键盘和鼠标，并提供可见焦点。

## 10. 分阶段实施

实施说明（2026-07-26）：

- P0、P1 的首个可玩闭环已完成，并已经拆分飞剑战斗 Integration。
- P2 已完成经验、确定性三选一、加剑和四条路线的基础数值升级；剑意与规则型升级未完成。
- P3 已完成基础敌潮、伤害反馈、失败和重开；精英行为、首领、胜利与长局验证未完成。
- 当前多路径剑阵仍是硬编码垂直切片，下一步先按后续计划迁移为数据驱动阵图。

### P0：从演示变成可运行的生存场景

- 把 `DemoSceneState` 的业务事实迁移到 Run/Player Entity。
- 增加 WASD、生命、敌人、生成 Director、追踪 AI 和敌我接触。
- 增加敌人渲染、HUD、失败和重开。

验收：可以移动、受伤、死亡和重开，持续运行 3 分钟无结构错误。

- 增加自动索敌和自动施放。

- 用 `FlyingSwordContactQuery` 产生伤害请求。

验收：穿云可以稳定击杀敌人；同一动作不会逐 Tick 重复结算。

### P2：升级与构筑

- 完成波次、精英、第 8 分钟首领、胜利结算。

- 加入压力模式和长局稳定性测试。

验收：从开始到胜利/失败形成完整闭环，压力模式无持续 GC 增长。

## 12. 首版非目标

- 永久货币、存档和局外天赋树；
- 随机房间、地图生成和可破坏地形；
- 联机同步；
- 通用伤害、属性、Buff npm 包；
