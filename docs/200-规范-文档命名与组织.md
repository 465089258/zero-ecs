# Zero ECS 文档命名与组织规范

> 类别：规范
> 状态：生效
> 权威性：规范性
> 适用范围：`docs`、README 中的文档入口
> 最后更新：2026-07-23
> 导航入口：[文档索引](./000-导航-文档索引.md)

本文规定仓库文档的文件命名、分类编号、状态元数据、链接和归档方式。目标是在文件系统、
编辑器快速打开和全文搜索中都能稳定定位文档，同时避免状态变化引起无意义的文件重命名。

## 1. 文件名格式

统一格式：

```text
NNN-类别-主题.md
```

示例：

```text
100-架构-架构宪法.md
230-规范-性能与分配.md
310-设计-Archetype-Query与Chunk生命周期收敛.md
710-计划-架构迁移执行方案.md
900-历史-开发计划.md
```

### 1.1 编号

- 使用三位十进制编号。
- 编号用于稳定排序和文档身份，不表示版本、优先级或状态。
- 已经进入主分支的编号不因新增文档整体重排。
- 同类文档优先以 `10` 为间隔分配，必要时插入中间编号。
- 文档用途发生根本变化时应新增替代文档，不通过跨类别改号掩盖历史。

### 1.2 类别

类别必须使用以下固定词表：

| 编号范围 | 类别 | 用途 |
| --- | --- | --- |
| `000–099` | 导航 | 文档索引、阅读路线、术语入口 |
| `100–199` | 架构 | 架构宪法、当前架构、分层与所有权 |
| `200–299` | 规范 | 开发、模块、性能和文档管理规范 |
| `300–499` | 设计 | 具体功能或机制设计 |
| `500–599` | 参考 | API、配置、命令和速查资料 |
| `600–699` | 指南 | 使用、迁移和排障指南 |
| `700–799` | 计划 | 实施计划和阶段验收 |
| `800–899` | 记录 | 架构决策、评审结论和性能结果 |
| `900–999` | 历史 | 只用于追溯的历史文档 |

类别由文档的长期用途决定，不由当前状态决定。计划完成后仍可保留在计划类别，只需修改状态；
只有明确不再描述当前事实的材料才进入历史类别。

### 1.3 主题

- 使用简洁中文表达主题，不重复“文档”“说明”等无区分度词语。
- `Game`、`World`、`Query`、`Chunk`、`Archetype`、`Scheduler`、`Commands`、
  `API`、`ECS` 等代码和公共 API 中的正式名称保留英文。
- 使用半角连字符 `-` 分隔编号、类别和主题。
- 不使用空格、下划线、括号、状态、版本号或日期。
- 文件名应尽量控制在 40 个字符左右；完整语义放入正文标题和摘要。

## 2. 标题和文件名

文件名服务于排序和检索，一级标题服务于阅读，两者不要求完全一致：

```text
文件名：
310-设计-Archetype-Query与Chunk生命周期收敛.md

一级标题：
# Archetype、Query 与 Chunk 生命周期收敛方案
```

一级标题必须唯一、自然可读，并与文档索引中的链接文字一致。

## 3. 文档元数据

每份现行文档必须在一级标题后提供统一引用块：

```md
> 类别：设计
> 状态：已评审
> 权威性：规范性
> 适用范围：`@zero-ecs/world`、`@zero-ecs/game`
> 最后更新：2026-07-23
> 上位文档：[架构宪法](./100-架构-架构宪法.md)
```

`上位文档`、`替代文档`、`导航入口` 等关系字段按需添加，不使用空占位字段。

### 3.1 状态词表

状态只能使用以下值：

| 状态 | 含义 |
| --- | --- |
| 草案 | 内容仍可大幅调整 |
| 评审中 | 正在收集和处理评审意见 |
| 已评审 | 设计已固定，尚未开始实施 |
| 实施中 | 对应代码、文档或验证正在进行 |
| 已完成 | 设计对应实现和普通验证已经完成 |
| 生效 | 当前必须使用或遵循 |
| 已延期 | 已评审，但暂不进入实施 |
| 已废弃 | 不再适用，必须指向替代文档 |
| 历史归档 | 只用于追溯，不描述当前事实 |

复杂进度不得发明组合状态，应使用一个主状态，并在元数据后的“实施说明”中描述已完成和延期
部分。

### 3.2 权威性

权威性只能使用以下值：

- `规范性`：发生冲突时具有约束力。
- `说明性`：描述当前实现或使用方式，不覆盖规范。
- `历史性`：只用于追溯。

规范性文档之间发生冲突时，以明确声明的上位文档为准；无法判断时必须发起评审。

### 3.3 日期

- 日期使用 `YYYY-MM-DD`。
- `最后更新`表示最后一次实质内容变更，不因纯格式化、改名或链接修复单独更新。
- 性能记录、发布记录等需要精确复现的文档可以另外记录执行日期和环境。

## 4. 链接规则

- 仓库内 Markdown 文档使用相对链接。
- 链接文字使用文档标题或可理解的简称，不使用裸文件名。
- 正文提及具有约束力的规则时应链接到对应规范，而不是复制一份容易失效的规则。
- 同一目录链接使用 `./文件名.md`。
- README 链接使用 `./docs/文件名.md`。
- 不保留内容重复的旧名称跳转文档；版本追踪由 Git 历史负责。

## 5. 索引规则

[文档索引](./000-导航-文档索引.md) 是 `docs` 的统一入口，至少维护：

- 推荐阅读路线；
- 文档编号和链接；
- 类别、状态和权威性；
- 一句话用途。

新增、重命名、废弃或改变状态时，必须同步更新索引。

## 6. 重命名事务

文档重命名必须一次完成：

1. 使用保留历史的文件移动操作；
2. 更新 README、docs 和其他源码中的全部引用；
3. 更新文档元数据和索引；
4. 搜索旧文件名，确认没有残留；
5. 校验全部 Markdown 相对链接目标存在；
6. 执行与文档内容相关的仓库门禁。

禁止在同一变更中长期保留新旧两份相同内容的文档。

## 7. 新文档检查表

- [ ] 编号位于正确类别范围且未被占用。
- [ ] 文件名符合 `NNN-类别-主题.md`。
- [ ] 一级标题和元数据完整。
- [ ] 状态和权威性使用固定词表。
- [ ] 必要时声明上位或替代文档。
- [ ] 已加入文档索引。
- [ ] 仓库内链接使用相对路径。
- [ ] 没有复制其他规范中的长段规则。
