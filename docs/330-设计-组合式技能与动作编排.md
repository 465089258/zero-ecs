本文保存当前已经讨论确认的组合式技能模型和复杂动作编排方案。它只描述未来上层玩法模块
的目标设计，不表示当前仓库已经提供对应实现。

## 1. 定位

技能系统采用“少量技能骨架、宝石改写技能图、冷路径编译运行计划”的模型：

```text
技能骨架 Skill Chassis
+ 宝石变换 Gem Transform
+ 角色属性与装备 Modifier
= 编译后的 SkillPlan
```

技能骨架负责发动和投送方式，宝石负责元素、载荷、投射行为、条件触发和动作形态。运行时
执行编译结果，不根据技能名称寻找特殊分支。

例如系统不存在独立的“冰霜射击”“爆炸射击”和“连锁射击”定义：

```text
射击
+ 寒霜灌注
+ 爆裂
+ 连锁
= 寒霜连锁爆裂射击
```

最终技能身份属于当前技能实例及其宝石组合，而不是预先枚举的内容类型。

## 2. 目标与非目标

### 2.1 目标

- 让少量基础动作形成大量可解释的技能组合。
- 元素、范围、投射行为和命中效果可以跨骨架复用。
- 复杂动作拥有稳定时序，不依赖动画回调驱动模拟。
- 相同组合编译为可共享的紧凑运行计划。
- 高频战斗请求在稳定容量下复用，不为每次命中创建对象。
- 技能组合可以生成可解释的数值、标签和表现配方。

### 2.2 非目标

- 不把每个最终组合实现为一个 Service、System 或 Component 类型。
- 不允许内容配置携带任意运行时闭包。
- 不使用 Timer 为每个冷却、射击间隔或动作阶段创建任务。
- 不让表现层动画完成事件决定权威模拟时序。
- 不为了一次技能动作频繁添加、删除角色 Component。

## 3. 技能骨架

技能骨架只拥有不能通过普通宝石安全表达的控制语义：

- 输入方式：点击、按住、蓄力、引导；
- 武器或媒介要求；
- 动作与基础时间；
- 目标选择方式；
- 初始投送形式；
- 基础伤害或效果来源；
- 可被宝石访问的语义端口。

新增技能骨架的判定规则是：

> 只有输入、动作、目标选择或生命周期发生根本变化时，才新增技能骨架。

因此冰霜、火焰、爆炸、穿透、连锁等不构成新骨架。部署物、持续引导、召唤或需要独立
控制生命周期的能力，可以成为新的骨架。

一个“射击”骨架可以提供：

```text
激活：弓攻击
动作：播放射击动作
投送：生成一个投射物
载荷：一次武器伤害
端口：OnLaunch / OnContact / OnHit / OnStop / OnExpire / OnKill
```

其初始能力包括：

```text
Attack
Bow
Projectile
WeaponDamage
CanHit
CanCrit
OnContact
OnStop
```

## 4. 宝石类型与能力约束

宝石通过能力声明适用范围，不直接判断技能名称：

```ts
interface GemDefinition {
    readonly requires: CapabilityMask;
    readonly excludes: CapabilityMask;
    readonly provides: CapabilityMask;
    readonly transforms: readonly SkillTransform[];
}
```

### 4.1 灌注宝石

修改载荷性质，例如伤害转化、异常状态和表现层：

```text
寒霜灌注
- 60% Physical → Cold
- 提供 Cold 与 Chill 能力
- 为投射物和命中添加寒霜表现层
```

### 4.2 投送宝石

修改投送数量和继续行为，例如多重投射、穿透、分裂、连锁和回旋。

### 4.3 行为宝石

向语义端口附加效果。例如普通爆裂可以在 `OnStop` 创建范围节点，并复制投射物当前载荷。
寒霜灌注与爆裂组合后，范围节点自然取得寒霜载荷，不需要专门的组合定义。

### 4.4 条件宝石

只在特定事实下附加效果，例如 `OnCrit`、`OnKill`、目标处于某状态或角色满足某资源条件。

### 4.5 动作形态宝石

重写技能的前台动作流程，例如蓄力、引导、凌空撤射或连续施放。这类宝石会争夺角色动作
控制权，同一技能默认只能安装一个互斥组内的动作形态。

## 5. 技能图与编译顺序

冷路径先构造具有语义端口的技能图：

```text
Activation
    │
    ▼
OnLaunch ──► Delivery
                │
                ├─ OnContact
                ├─ OnHit
                ├─ OnStop
                ├─ OnExpire
                └─ OnKill
```

宝石修改明确的节点或端口，而不是向运行时增加技能名称分支。安装顺序不应隐式改变结果；
编译器使用固定阶段：

1. 能力、依赖和冲突校验；
2. 激活方式改写；
3. 投送结构改写；
4. 载荷和元素转换；
5. 命中、停止、击杀等行为挂接；
6. 数值 Modifier；
7. 成本、冷却和伤害效能计算；
8. 表现配方生成；
9. 扁平化为紧凑 `SkillPlan`。

相同骨架、宝石、等级和拓扑 Modifier 必须生成相同缓存键。普通临时 Buff 只使角色数值表
失效；只有改变技能结构、能力或节点的 Modifier 才重新编译 SkillPlan。

运行计划可以使用数字化指令数组：

```ts
interface CompiledSkillPlan {
    readonly id: number;
    readonly capabilities: CapabilityMask;
    readonly opcodes: Uint16Array;
    readonly flags: Uint16Array;
    readonly argsU32: Uint32Array;
    readonly argsF32: Float32Array;
}
```

具体布局必须在实现前结合目标平台基准评审，本文不提前固定字段排列。

## 6. 与当前 ECS 的组合边界

### 6.1 数据归属

| 类型 | 归属 |
| --- | --- |
| 技能、宝石、能力和表现目录 | Resource |
| 编译计划与派生属性缓存 | Service |
| 技能请求、动作、命中、触发和战斗结果队列 | State |
| 已装备技能实例 | Entity + Component |
| 投射物、持续区域、陷阱、召唤物 | Entity + Component |
| Buff、Debuff 等高频逻辑状态 | 紧凑 Status State |
| 内容编译、属性查询和技能请求入口 | Service |
| 时间推进、动作执行、碰撞和结算 | System |

### 6.2 同 Tick 可见性

当前 Commands 的结构变化在 `Update.post` 提交，固定阶段创建的 Entity 在提交前不能被 Query
观察。因此：

- 立即命中、伤害、状态和触发使用 State 中的高水位 SoA 队列；
- 投射物、区域和召唤物通过 Commands 创建，并从后续固定 Tick 开始参与模拟；
- 复杂触发链在一个有操作数和深度上限的战斗波次循环中处理；
- Event 主要服务低频观察和表现，不承载每次命中的核心结算。

推荐的逻辑顺序是：

```text
StatRefresh
→ SkillIntent
→ SkillAction
→ Movement
→ SpatialIndex
→ Projectile
→ Collision
→ StatusPulse
→ CombatResolve
→ Death
→ Feedback
→ Update.post Commands / Structure / Events
```

### 6.3 冷却与持续时间

技能冷却、充能和状态持续时间保存截止 Tick，并在访问或对应 System 中更新，不为每个对象
注册 Timer 任务。

## 7. 动作编排示例：凌空撤射

需求：

> 释放射击技能时先跳起，在空中连续射击并后退，最后射出一支威力巨大的箭，然后落地。

该效果定义为射击骨架的独占动作形态宝石，而不是新的射击技能：

```text
射击 Skill Chassis
+ 凌空撤射 Action Form Gem
+ 其他元素、投射和命中宝石
= 最终技能
```

### 7.1 技能图改写

```text
Activate
→ Takeoff
→ Airborne Retreat
   ├─ Emit Volley Shot 1
   ├─ Emit Volley Shot 2
   ├─ Emit Volley Shot 3
   └─ Emit Volley Shot 4
→ Emit Finisher Shot
→ Landing
→ Recovery
```

宝石要求 `RangedEmission`、`Projectile`、`Grounded` 和 `CanUseActionMotion`，提供
`Sequence`、`Airborne`、`Retreat`、`RepeatedEmission` 与 `Finisher`，并与其他前台
动作形态冲突。

### 7.2 示例时间线

```text
Tick 0   校验、扣资源、进入冷却、创建 Action
Tick 1   起跳并开始后退
Tick 6   普通箭 1
Tick 10  普通箭 2
Tick 14  普通箭 3
Tick 18  普通箭 4
Tick 24  终结箭
Tick 30  落地并解除动作锁定
```

实际时点在动作开始时根据攻击速度计算一次。攻击速度可以缩短整个动作持续时间，但跳跃
高度和后退总距离保持不变。

### 7.3 动作运行状态

动作不使用 Timer 或临时 Entity。`SkillActionState` 只保存当前活跃动作的紧凑记录：

```text
caster
skill
planId
actionSequence
startTick
nextEventTick
phase
emissionIndex
target
aimX / aimY
retreatX / retreatY
durationTicks
```

普通前台动作占用角色动作槽；不控制角色位移的被动触发技能可以继续进入 EffectWork 队列。

### 7.4 跳跃与移动

动作系统计算跳跃进度和期望后退位移，通过 Movement 模块的请求契约处理水平碰撞，不直接
绕过移动规则写入 Position。二维俯视游戏可以把高度保存为独立表现/战斗字段：

```text
elevation = jumpHeight × 4 × progress × (1 - progress)
```

“Airborne”不自动表示无敌、不可选中或忽略地面效果。这些战斗规则必须由宝石参数明确声明。

### 7.5 连射与终结箭

动作计划暴露两个发射端口：

```text
VolleyEmission
FinisherEmission
```

普通箭使用较低载荷系数并携带 `Volley` 标记；终结箭使用较高载荷系数并携带 `Finisher`
标记。两者都复用当前技能已经经过灌注和行为宝石修改的载荷。

默认组合规则：

- 元素转换、穿透、连锁和兼容的命中行为可以作用于全部箭；
- 多重投射默认只匹配带 `Repeatable` 的 Volley；
- Finisher 默认带 `SingleProjectileLocked`，保持最终箭只有一支；
- 专门要求 `Finisher` 的高阶宝石可以解除单发限制或只为终结箭附加爆炸；
- 普通 `OnStop` 爆裂会作用于全部兼容投射物。

### 7.6 瞄准、中断与成本

- 起跳时锁定后退方向；
- 射击方向可以追踪原目标，目标失效后使用最后有效方向；
- 起跳时扣除资源并开始冷却；
- 眩晕、击飞或死亡可以取消剩余动作；
- 中断不返还默认资源和冷却；
- 终结箭尚未发射时被中断，不补发终结箭；
- 后退被场景阻挡只缩短位移，不自动取消技能；
- 模拟 Tick 驱动动画进度，动画回调不反向推进模拟。

## 8. 组合与平衡约束

### 8.1 元素转换

底层编译器可以允许多种灌注共存，但必须验证转换方向、比例和循环。是否通过普通规则、
装备或高级能力开放多元素组合，属于上层玩法设计。

### 8.2 伤害效能

复制载荷的节点必须携带显式伤害效能。例如多重投射、爆裂、分裂和连锁分别调整自身生成
分支，不能依赖隐藏的全局倍率。

### 8.3 命中组

同一次动作和发射波次携带稳定 `actionSequence`、`emissionIndex` 与 HitGroup。默认可以
限制同一波多投射物对同一目标重复命中；解除限制必须是明确能力。

### 8.4 复杂度容量

可以使用技能复杂度容量约束高阶组合，替代单纯的固定宝石数量。具体成本、装备来源和
互斥规则仍属于待评审玩法内容，不在本通用设计中固定。

## 9. 表现组合

表现层应从同一编译结果生成分层配方，而不是为每种组合制作独立资源：

```text
基础动作与模型
+ 元素材质和轨迹
+ 投送行为表现
+ 命中或终止表现
+ 动作形态表现
```

例如寒霜、爆裂、连锁和凌空撤射分别贡献可组合的视觉层，不查找一个预制的
`frost_explosive_chain_aerial_shot` 资源。

## 10. 安全与性能边界

- 热路径执行数字化 SkillPlan，不遍历作者对象图。
- 高频队列使用 `used` 游标和高水位复用，新峰值才扩容。
- 触发链必须具有最大深度、每 Tick 操作数和自递归限制。
- 结构变化统一通过 Commands，不在 Query 迭代中即时迁移实体。
- 冷路径允许 Map、Set、数组和诊断对象，不为了未证明的收益提前池化。
- 任何零分配或性能结论都必须按照性能规范建立固定工作量和基准。
