## 1. 当前代码基线

当前工作树已经包含但尚未形成新基线提交的能力：

- 剑夹、神识、受控剑与后备剑 Tag；
- 单剑伤害、攻击间隔、飞行能力和灵力；
- 飞剑 Offer 实体及升级卡属性展示；
- 灵力耗尽后的受控/后备剑迁移；
- 人物法力、剑阵持续消耗和集火全法力爆发；
- 身剑合一聚剑与突进阶段；
- 四种剑意基础切片及独立伤害种类。

现有缺口：

1. `AddSword` 在剑夹已满时直接失效，没有替换事务。
2. Offer 的 Blueprint 只是数值，尚无权威剑器模板目录。
3. `DamageRequest` 结算生命后立即销毁，没有实际扣血量和恢复受益人事实。
4. 不存在统一 `HealingRequest`、自然恢复、吸血、击杀恢复和生命掉落物。
5. 升级目录只有名称与描述，缺少类别、最大等级、前置和互斥规则。
6. 首领、胜利结算和八分钟完整局仍未完成。

## 2. 开发约束

- 所有新增能力只进入 `examples/flying-sword`。
- 低频装备、受控/后备、替换和能力获得使用组件或 Tag 迁移。
- 热路径在逐行循环前缓存 Chunk 列。
- 稳定帧不创建逐命中对象、数组、闭包或 Map。
- 每次伤害可以创建已有短生命周期伤害事实，但不能再创建长期逐命中吸血实例。
- 二次触发伤害默认不吸血，不通过运行时 `DamageKind` 大型分支推导资格。
- 本 Tick 伤害产生的吸血下一 Tick 才能恢复。
- 生命为 0 的实体不能被普通恢复复活。
- 玩法数值进入 `RogueRunTuning`、内容目录或 ECS 组件，不散落在 System 常量中。
- 不在同一提交中同时修改装备事务、恢复管线和首领行为。

## 3. 评审启动门

进入代码阶段前固定以下决定：

| 决定 | 计划默认值 |
| --- | --- |
| 吸血计算伤害 | 使用目标本次实际扣除的生命，过量伤害不产生额外吸血 |
| 单次吸血上限 | 最大生命的 5% |
| 最大吸血储备 | 最大生命的 40% |
| 储备释放基准时间 | 3.33 秒 |
| 每秒吸血恢复上限 | 最大生命的 12% |
| 满血行为 | 清空吸血储备 |
| 二次伤害 | 雷链、火爆、破势不参与吸血 |
| 命中回血 | 第一阶段不实现 |
| 满剑夹 | 选择一把现有剑替换或放弃新剑 |
| 动作中的被替换剑 | 添加等待退役 Tag，动作结束后完成替换 |

任一决定改变时，先更新上位设计，再调整对应阶段，不在实现中隐式改变。

## 4. 目标系统顺序

现有 `Damage` 阶段需要拆出结算后事实和清理边界：

```text
Clock
→ RecoveryGenerate
→ RecoveryResolve
→ Spawn / Intent / Motion
→ Contact
→ DamageEffects
→ DamageResolve
→ LeechAccumulate
→ DamageFactCleanup
→ Death
→ Progression
→ OpenUpgrade
```

- `RecoveryGenerate` 读取上一 Tick 的吸血储备、自然恢复及延迟恢复来源；
- `RecoveryResolve` 统一修改生命并产生实际恢复表现事实；
- `DamageResolve` 写入实际扣除生命，不立即销毁伤害实体；
- `LeechAccumulate` 只消费具有明确资格与受益人的结算后伤害；
- `DamageFactCleanup` 在所有伤害消费者完成后销毁事实；
- `Death` 在吸血累计后执行，但新吸血尚未恢复生命。

## 7. 阶段 2：满剑夹替换事务（已完成）

### ECS 事实

```ts
export enum SwordReplacementSelection {
    Offer,
    Container,
}

export enum ReplaceSwordRequest {
    Offer,
    Outgoing,
}
```

需要等待当前动作完成的旧剑继续使用 `PendingFlyingSwordRetireTag`。替换事务不能只存在于
DOM 或 Service 字段。

### 流程

```text
选择“获得飞剑”
→ 剑夹未满：直接生成
→ 剑夹已满：暂停并打开替换面板
→ 选择旧剑或放弃
→ 后备剑立即替换
→ 动作中的受控剑标记等待退役
→ 动作结束后复用原 InventorySlot 生成新剑
→ 重新归并神识控制位
```

Offer 在事务完成或放弃前保持存活。表现层显示新旧剑逐项对比，以及受控、后备、灵力
不足和动作中状态。

### 测试

- 未满直接收入；
- 已满进入替换而不丢失 Offer；
- 替换后备剑和动作中受控剑；
- 放弃 Offer；
- `InventorySlot` 稳定复用；
- 同批 Commands 不产生同时受控与后备的非法剑。

## 8. 阶段 3：统一生命恢复管线（已完成）

### 组件

```ts
export enum HealingRequest {
    Source,
    Target,
    Amount,
    Kind,
}

export enum HealingKind {
    Regeneration,
    Leech,
    OnKill,
    Pickup,
    Skill,
}

export enum ResolvedHealing {
    Applied,
    Overflow,
}

export enum LifeRegeneration {
    FlatPerSecond,
    MaximumLifePerSecondRatio,
}
```

`HealingKind` 只用于表现和统计；是否拥有恢复能力由组件和 Query 决定。

### System

1. `generateLifeRegenerationSystem`
2. `resolveHealingRequestsSystem`
3. `cleanupHealingFactsSystem`

```text
Applied = min(max(Amount, 0), Maximum - Current)
Overflow = max(Amount - Applied, 0)
```

生命为 0 时 `Applied` 为 0。恢复表现读取 `ResolvedHealing.Applied`，不显示溢出恢复。

### 测试

- 最大生命、负数、NaN、满血溢出和死亡禁止恢复；
- 同 Tick 多请求确定性累加；
- 表现只使用实际恢复量；
- 稳定帧每名恢复者最多产生一个自然恢复请求。

## 9. 阶段 4：结算后伤害事实与吸血储备

### 伤害事实迁移

```ts
export enum DamageAttribution {
    Beneficiary,
}

export enum ResolvedDamage {
    Applied,
}

export class LeechEligibleDamageTag implements ComponentTag {}
```

直接飞剑伤害和身剑合一添加归因与吸血资格。雷链、火印爆发、破势等二次伤害不添加
资格 Tag。

`resolveRogueDamageSystem` 改为：

1. 计算目标实际扣除生命；
2. 将请求迁移为带 `ResolvedDamageType` 的结算后事实；
3. 由吸血、统计和表现 System 消费；
4. 最终统一清理。

### 吸血组件

```ts
export enum LifeLeechStats {
    GlobalDamageRatio,
    MaximumPerHitRatio,
    MaximumStoredRatio,
    ReleaseDuration,
    MaximumRecoveryPerSecondRatio,
}

export enum LifeLeechRuntime {
    Stored,
}

export enum SwordLifeLeech {
    DamageRatio,
}
```

单剑吸血只作用于该剑自己的直接伤害。全局吸血与来源剑吸血相加后再应用单次上限。

### System

- `accumulateLifeLeechSystem` 增加 `Stored`；
- `generateLifeLeechRecoverySystem` 在下一 Tick 产生一个聚合恢复请求；
- 满血时清空储备；
- `cleanupResolvedDamageFactsSystem` 最后销毁结算后伤害事实。

### 数值与性能测试

- 2000 伤害和 1% 吸血受 5% 单次上限限制；
- 过量伤害按实际扣血量计算；
- 多剑齐射不超过 40% 储备；
- 恢复速度不超过每秒最大生命的 12%；
- 满血清空，同 Tick 致死伤害不能被新吸血挽回；
- 二次伤害不参与；
- 500 剑同时命中不创建 500 个长期吸血实体；
- 热循环无 Map、数组、对象或闭包分配。

## 17. 完成定义

P2.5 完成必须同时满足：

- 四种剑器模板、确定 Offer 和满剑夹替换可用；
- 剑夹与神识形成续航和并发两条不同成长轴；
- 所有生命恢复通过统一请求结算；
- 高伤、高频和多剑吸血均受三重上限；
- 击杀恢复与生命灵蕴有独立上限和反馈；
- 升级目录支持类别、等级、前置与互斥；
- 至少两种装备构筑和两种生存构筑能够完成 6 分钟混合敌潮；
- 全量自动门禁通过，人工试玩无阻塞问题；
- 相关文档状态与当前代码一致。
