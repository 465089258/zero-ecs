## 1. 定位

`@zero-ecs/motion` 是服务 ECS Entity 的领域无关运动扩展。它不定义另一套向量或位置，
而是消费 Math 组件并执行批量运动积分：

```text
@zero-ecs/game
       ↑
@zero-ecs/math
       ↑
@zero-ecs/motion
       ↑
角色 / AI / 飞剑 / 投射物 / 其他领域包
```

Motion 可以依赖 Game 和 Math 公共入口，不得依赖 World、Scheduler、飞剑、角色、技能、
属性、表现或 Integration 实现。Game 与 Math 不反向依赖或重导出 Motion。

当前公共入口：

```text
@zero-ecs/motion
@zero-ecs/motion/3d
```

## 2. 输入与事实

第一阶段提供 `MoveTowards3Type`：

```text
TargetX / TargetY / TargetZ
MaximumSpeed / Acceleration / ArrivalRadius
```

它表达调用方已经归并完成的最终运动输入。目标可能来自玩家输入、AI、技能轨迹、编队、
网络同步或属性投影；Motion 不知道来源，也不在运行时读取上游目录和对象图。

参加 `moveTowards3System` 的 Entity 同时持有：

```text
Position3Type
PreviousPosition3Type
Velocity3Type
Direction3Type
MoveTowards3Type
```

Position、PreviousPosition、Velocity 和 Direction 是通用数学事实，归 Math 所有；
MoveTowards 是运动算法输入，归 Motion 所有。领域组件可以保存自身的原始目标或基础属性，
并在 Motion 之前把它们归并到最终输入。

## 3. 固定 Tick 语义

`Motion3Module` 把 `moveTowards3System` 安装到：

```text
Update.fixed
└─ MotionSystemSet.Integrate3
```

每个固定 Tick 对匹配 Entity 执行：

```text
Position → PreviousPosition
→ 计算目标方向和期望速度
→ 按 Acceleration 限制速度变化
→ 积分 Position
→ 在速度非零时更新 Direction
```

到达半径内的期望速度为零；接近目标时按距离降低速度，避免高速越过目标后持续振荡。
Motion 不添加或删除组件，也不决定“移动命令是否完成”。需要瞬态移动状态的领域或示例
应在 `MotionSystemSet.Integrate3` 之后判断到达，并通过 Commands 移除自己的状态标记。

## 4. 调度集成

产生最终输入的系统必须在 Motion 之前运行，消费移动结果的系统必须在 Motion 之后运行：

```ts
before: MotionSystemSet.Integrate3
after: MotionSystemSet.Integrate3
```

飞剑 Formation 产生领域编队目标，Guidance 在 Motion 前将默认编队或技能轨迹写入
`MoveTowards3Type`；Contact 在 Motion 后使用新位置推进技能阶段。这个顺序依赖稳定
SystemSet，不依赖 Motion 的具体系统函数。

## 5. 结构与生命周期

`MoveTowards3Type` 适合需要每 Tick 持续追踪目标的 Entity。是否长期保留由上层领域决定：

- 持续具有自主运动能力的飞剑可以长期保留；
- 只在收到命令时移动的角色可以按领域设计长期保留输入，并用瞬态命令标记表达活跃状态；
- 完全不需要目标追踪的 Entity 不应为布局统一而添加该组件。

Motion 不提供 FlyingSword、Character、Projectile 等专用组件，也不把输入来源编码为枚举。
新增算法应使用新的语义输入组件和 SystemSet；不能不断向 `MoveTowards3Type` 追加转向、
弹道、碰撞或领域状态，重新形成宽组件。

## 6. 性能与 GC

- Query 按 Archetype Chunk 批量遍历。
- Chunk 入口缓存全部 TypedArray 列，逐实体循环只访问局部列和 number。
- 稳定热路径不创建临时向量、结果对象、数组、元组、闭包或每实体命令。
- PreviousPosition 与其他结果直接写入 ECS 组件列。
- 不通过通用对象数学 API 包装逐实体运算。
- 数学开方和归一化只服务当前行，不缓存跨 Entity 临时状态。

结构迁移由拥有生命周期语义的上层模块负责；Motion 的稳定积分 System 不直接调用
Commands 或 World 迁移。

## 7. 当前范围与后续

当前已实现 3D 目标追踪、加速度限制、减速到达、固定帧历史位置和方向更新，并由飞剑与
示例角色共同复用。后续候选包括：

1. 2D 目标追踪，与 3D 保持相同字段语义和调度边界。
2. 旋转朝向、角速度和独立转向约束。
3. 可组合的阻尼、重力和弹道输入，但必须避免单个万能运动组件。
4. 面向连续大量 Entity 的正式 JIT、`--jitless` 和 Chromium 基准。

碰撞、寻路、轨迹作者工具、属性计算和表现插值不属于当前 Motion 包。
